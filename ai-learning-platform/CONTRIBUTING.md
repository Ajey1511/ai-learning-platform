# Contributing

1. Create a feature branch from `main`.
2. Keep API schemas, services, persistence, and UI concerns in their existing modules.
3. Add or update tests for behavior changes. Do not add credentials or real student data.
4. Run backend tests and `npm run build` before opening a pull request.
5. Mark synthetic datasets and avoid unverified employer claims.

Pull requests should explain the behavior change, database migration impact, and verification performed.
